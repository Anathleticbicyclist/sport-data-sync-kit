**全局通用机制（各卡不再重复）**

- 同步去重记忆键：`{源short}_{活动id}_to_{目标short}`，存 `synced_ids`；success / skipped 分支写记忆键，**pending 分支不写**。

## 二、已接平台卡片

### 2.1 iGPSPORT 国内 — `igp`（双向）

- **鉴权方式与凭证**：WebView 打开登录页 `login.passport.igpsport.cn`，`evaluateJavascript` 读 `localStorage['persist:app-store']` 的 `global.token`（令牌），再调 API 校验；无效清缓存重登（最多 2 次）；另有原生短信登录通道（`IGP_NATIVE_LOGIN`）。Prefs 键：`凭证键`。
- **列表接口**：
  - 方法/路径：`GET {BASE_CN}/web-gateway/web-analyze/activity/queryMyActivity`，`BASE_CN=https://prod.zh.igpsport.com/service`。
  - 参数位置：**query string**，`pageNo` / `pageSize=20` / `reqType=0` / `sort=1`。
  - 分页契约：服务端「最新在前」；返回 `code=0`、`totalRows` / `totalPage`；`pageNo=0` 服务端 `code=1003` 服务器异常、0 条；当前客户端一次只取一页，未循环补足。
  - 错误码文案：`code=1003` 空响应；非 200 见 `iGPSPORT API error:` 分支。
- **下载**：
  - **两段式**：先调 `getDownloadUrl`（`/web-gateway/web-analyze/activity/getDownloadUrl`）换取 OSS 直链 `downloadUrl`，再按直链取 FIT 文件。
  - 格式：FIT；OSS 直链形如 `igp-zh.oss-cn-hangzhou.aliyuncs.com/*.fit`。
  - 已知限制：经第三方 OSS 导入的「kp_」等记录，服务端可能判归属他人 → HTTP 403，`{"code":1002,"message":"不能下载他人运动记录"}`，客户端只能按无权限跳过/透出原文。
- **上传**：
  - 三步：①`getSignedUrl`（`/service/sportg/third-party-server/oss/getSignedUrl?fileExtension=.`）→ ②OSS PUT 直传（**不带 Content-Type**，仅 403/400 才带）→ ③`uploadByOss`（`/service/web-gateway/web-analyze/activity/uploadByOss`）。
  - 成功判据：`code∈{200,0}` 即成功；**异步解析，`data` 为空也判成功**。
  - 异步入库：是；当前异步分支 `pending=false`（未打待确认标记），回 ACK 即写记忆键，平台侧解析失败会被永久跳过。
  - 时区：`iGP 时区平移方法` 按「当天/历史」分治——同一天不动，历史 `FIT 处理逻辑.shift(+28800)`；与设置页三选一配套。
- **已知坑与限制**：
  - 列表把「跳过 N 条」直接当 `pageNo`，无 `(skip/size)+1` 换算；跳过=0 → `pageNo=0` 必失败。
  - 字段名缺口：列表映射 `rideDistance` / `totalMovingTime` / 点分 `startTime`，`extra/distance/duration` 可能为空，只影响显示与文件名，不影响下载字节。
  - 基线发布包曾把下载分发表比较值改坏（比较值 1→0），导致 iGP 不落下载分支；维护基线该处为正确比较值 1。

### 2.2 iGPSPORT 国际 — `igpen`（双向）

- **鉴权方式与凭证**：同国内链路，国际登录入口 `https://prod.en.igpsport.com/`；Prefs 键：`凭证键`。
- **列表接口**：`GET {BASE_INT}/web-gateway/web-analyze/activity/queryMyActivity`，`BASE_INT=https://prod.en.igpsport.com/service`；参数与分页契约同国内。
- **下载**：两段式，FIT；同国内 `getDownloadUrl` → OSS 直链。

- **已知坑与限制**：与国内共用时区/异步/pending 缺陷；国际站个别记录是否同样存在归属 403，待真机验证。

### 2.3 行者 — `xz`（双向）

- **鉴权方式与凭证**：`CookieManager` 取 `sessionid` + `凭证键`，`会话校验方法` 校验；Prefs 键：`凭证键`。
- **列表接口**：
  - 方法/路径：`GET https://www.imxingzhe.com/api/v1/pgworkout/?offset=&limit=`，Cookie 鉴权；请求头带 `Referer: https://www.imxingzhe.com/xingzhe/workouts/list`。
  - 参数位置：**query string**，`offset` / `limit`；分页为 offset 游标。
  - 错误码文案：响应解析 `code` / `data`；具体错误码文案未逐条复核（待真机验证）。
- **下载**：
  - `对应平台客户端.downloadGpxOrFit(cred, id, preferGpx)`；GPX / FIT 均可；**目标=iGP 时优先 GPX**；FIT 分支内已挂 `FIT 处理逻辑.normalize`。
  - 时间归一化：按 FIT 内 `local_timestamp - timestamp` 差值决定是否平移；注意实测记录指出字节码基线实际为 `delta==0 → 原样`、`delta≠0 → shift(+28800)`，与旧表述相反，**以字节码基线为准**。
- **上传**：
  - 路径：`POST https://www.imxingzhe.com/api/v1/fit/upload/`。
  - 字段名：`fit_file` + `md5`。
  - 成功判据：`code==0 && workout_id>0`；`workout_id` 字段名实证。
  - 重复判重：返回 `9006` / 「文件已上传」→ 记为跳过。
  - 格式：强制 FIT。
- **已知坑与限制**：
  - 时区是「下载端归一化 + 上传端用户开关」双轨，改任一端都可能叠加成 ±16h；行者时区修正须保持「不调整」。
  - 行者 GPX 上传时先 `FIT 处理逻辑.fixGpxTime(-8)` 回 UTC，再按目标时区 +8。

### 2.4 迈金（顽鹿 OTM）— `mg`（双向）

- **鉴权方式与凭证**：token 直接进 `Authorization` 头（非 令牌 封装）；Prefs 键：`凭证键`（access）。
- **登录/刷新接口**：
  - 账号密码登录：`POST https://otm.onelap.cn/api/login`，响应 `data` 内取 `token` + `refreshToken`。
  - 刷新：`POST https://otm.onelap.cn/api/token`，body `{"token": 旧 refreshToken, "from":"web", "to":"web"}`；响应**只解析 `data.token`（新 access）**，不读取/回写新 `refreshToken`。
  - JWT：`令牌剩余时长计算方法` 解 payload `exp`；实测 access ≈48h、refresh ≈58 天；无 exp/解析失败返回 null。
- **列表接口**：
  - 方法/路径：`POST https://otm.onelap.cn/api/otm/ride_record/list`。
  - 参数位置：**分页参数只认 query string**；`page` / `limit` 放进 JSON body 会被服务端忽略（body 版 `current_page` 恒为 1，永远第 1 页）；`?page=pageNo&limit=size`（body 空 `{}`）才生效。
  - 分页契约：返回 `code=200`、`total` / `total_pages` / `pagination.has_more` / `current_page`；服务端最新在前。
  - 错误码文案：HTTP 401 或 body `code=401` → 抛「迈金登录已过期，请重新登录」；body `code=200` 为成功；列表空响应文案「列表空响应」；「迈金列表错误: 」。
  - **历史问题**：早期版本曾把 HTTP 403 也并入该重登分支（更早版本只判 401），非鉴权类 403 会被误报成「请重新登录」。
- **下载**：
  - 两段：`/api/otm/ride_record/analysis/` → `/api/otm/ride_record/analysis/fit_content/`。
  - 格式：FIT；`fromFitContent` 经 `FIT 处理逻辑` 做 **GCJ-02 → WGS-84**，受全局开关 + 任务开关控制。
- **上传**：
  - 路径：`https://otm.onelap.cn/api/otm/ride_record/upload/fit`。
  - 字段名：**必须是 `jilu0`**（改名字段服务端不收）；`Authorization` 直接带 token。
  - 成功判据：HTTP 200 且 `success_count >= 1`。
  - 异步入库：是，**约 15–20s 入库**；当前 `pending=false`，回 ACK 即写记忆键。
  - 重复判重：以本端记忆键为准；平台侧去重规则未核实。
- **已知坑与限制**：
  - 刷新链路：除启动检测一处 `<1h` exp 预检外，列表/下载/上传前均无主动刷新；401 后仅按异常文案含「过期」/「401」被动刷一次并重试一次；**上传链路无刷新、无重放**。
  - refreshToken 不回写：若服务端轮换 refreshToken，本地存旧值，二次刷新静默失败 → 被迫重登；是否轮换属服务端行为，待实测。
  - 上传无 exp 预检、无 401 重放；非 200 直接失败。

## 四、遗留与复核提示

1. **异步入库记忆键风险**：iGP、迈金回 ACK 即 `success=true` 并写记忆键，pending 未置位；平台侧异步失败会被永久跳过。Outbase 是唯一按文案置 pending 的平台。
2. **两套代码基线不同步**：改动以官方字节码基线为准；本地维护基线部分文件滞后（版本号、佳明明文分支等）。
3. **时区三套并存**：下载端 `FIT 处理逻辑`、上传端 `localTimeTargets` GPX ±8、iGP 专用 `iGP 时区平移方法`；改动任一端都要防叠加 ±16h。
4. **待实测项汇总**：黑鸟/捷安特/高驰/Wahoo/Intervals.icu/CyCity 上传成功谓词未逐条复核；咕咚/Zepp/两步路接口字段待真机抓包；实验室五家全部待真机验证。
5. **本备忘未覆盖**：课表同步（`上传路由`）、热力图、轨迹合并/贴纸、码表子功能，见本知识库代码导览对应章节。

> 本文档由本地 md 实证与客户端代码核对整理；凡标「待实测/未核实」者，均未在本环境登录平台验证，对接前需真机回归。
